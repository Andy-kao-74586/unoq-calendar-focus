# UNO Q 智慧日曆計時器

UNO Q 讀取 Google 主日曆，自動切換準備提醒、當下活動倒數與空閒畫面。網頁顯示完整活動名稱；實體 LED 輪播英文提示與剩餘時間。不用按「開始專注」才會對行程產生反應。

## 升級安裝

1. 停止舊 App，保留作為備份。匯入 `unoq-smart-calendar-timer.zip`。
2. 執行 **UNO Q 智慧日曆計時器**，確認 Python 與 Sketch 均成功啟動。
3. 用 Chrome／Edge 開啟 http://localhost:7000 。App Lab 若開啟 http://127.0.0.1:7000 ，新版會自動轉到 localhost。必要時 Ctrl+F5 更新快取。
4. 用原本的 Google OAuth Web 用戶端 ID 重新連接日曆，不需要重建 Google Cloud 專案。詳細設定見 GOOGLE_SETUP.md。
5. 連接成功後預設開啟「自動跟隨日曆」。也可取消勾選，回到原本的專注計時器。

只需 UNO Q 與 USB 線。電腦及板子都需能連上網路。App 停止或板子斷電會清除本次授權、設定、計時與完成輪數。

## 自動反應

例如日曆有 17:00～18:00「晚餐」，準備時間 5 分鐘：

| 時間／狀況 | 網頁 | 板上 LED |
|---|---|---|
| 16:55 前，未啟動專注 | 目前空閒、距離下一個定時行程的倒數 | FREE 跑馬燈與距離開始的時間 |
| 16:55～17:00 | 準備出發：晚餐，倒數到 17:00 | READY 跑馬燈與準備倒數 |
| 17:00～18:00 | 正在進行：晚餐，倒數到 18:00 | DINNER 跑馬燈與行程剩餘時間 |
| 行程結束 | 回到空閒；若有接續行程就直接切換 | FREE 或下一個活動提示 |
| 中途開啟 App | 授權同步後直接加入當下行程倒數 | 例如 17:20 顯示約 40m，不會重新算一小時 |
| 改期／取消 | 下次成功同步後重新判斷場景與剩餘時間 | 對應更新 |

已讀取的行程由板子約每 0.1 秒判斷邊界，不需要等下一次 Google API 請求才切換。網頁約每 0.5 秒更新。Google 資料每 60 秒同步，手動同步至少間隔 10 秒。這不是即時推播；修改行程需等待同步。

## 專注如何與行程共存

- 空閒時仍可手動開始專注，或使用「依建議開始專注」，保留休息與準備時間。
- 自動跟隨開啟時，準備／活動畫面優先。正在執行的專注或休息會暫停，不把中途暫停的專注計成完成。
- 行程結束後保留暫停的時間，按「繼續」才會恢復，不會在背景自動消耗它。
- 活動／準備倒數不能暫停或重設；「重設本輪」只重設專注計時。若要在活動中手動專注，先取消自動跟隨。
- 專注結束自動開始休息，休息結束等待手動開始下一輪。示範模式仍是 30 秒專注、10 秒休息，不會縮短真實日曆活動。
- 關閉自動跟隨後，原本「依建議開始」的最晚停止時間仍有效；重設可取消該輪。

建議專注分鐘 = min(希望專注分鐘, floor((下一個忙碌行程開始 − 準備時間 − 現在) / 60) − 休息分鐘)。不足一分鐘或有忙碌活動時，不提供建議開始。

## 跑馬燈與文字

8×13 LED 使用原創 3×5 ASCII 字型。每輪先完整捲動提示，再顯示倒數 5 秒，持續交替。跑馬燈播放時倒數仍在背景繼續。網頁的小矩陣是預計畫面，不是攝影機回傳。

| 標題關鍵字 | LED 提示 |
|---|---|
| 晚餐／dinner | DINNER |
| 午餐／lunch | LUNCH |
| 早餐／breakfast | BREAKFAST |
| 會議／討論／meeting | MEETING |
| 上課／課程／class | CLASS |
| 讀書／複習／study | STUDY |
| 運動／健身／跑步／workout | SPORT |
| 睡覺／睡眠／sleep | SLEEP |
| 未辨識的中文活動 | EVENT |

可以在 Google 日曆標題加英文短名，例如 `生日 [CAKE]`，LED 就顯示 CAKE；英文標題直接顯示，最多 20 字元。這是關鍵字規則，並非 AI 理解活動。完整中文名稱保留在網頁，LED 不提供任意中文字型。

倒數 >=60 秒時顯示向上取整分鐘，例如 24:32 顯示 25m；最後 59 秒顯示秒數。100～999 分鐘顯示三位數，大於 999 分鐘則顯示向上取整小時及 H。頂部中間亮點是日曆模式；底列顯示活動／準備剩餘比例。SYNC 表示日曆資料不可用；X 表示 MCU 超過 5 秒沒有收到 Python 更新。

## 邊界與限制

- 只讀 Google **主日曆**未來 24 小時內開始、或目前仍在進行的活動；不修改日曆。不支援其他共享／課表日曆。
- 全天忙碌活動會阻擋專注建議，但不啟動整天倒數，也不遮住定時活動。
- 同時有多個定時活動：優先最早開始者；同時開始者選最早結束者，網頁提示重疊數量。
- 取消、標成「有空」、自己已拒絕的活動與工作地點事件不觸發場景。
- 同步失敗、超過 120 秒沒有成功更新，或授權到期：不根據過期資料啟動活動。空閒畫面顯示 SYNC；暫停中的專注保留。已設定的專注停止時間仍可能生效。
- 授權只保存在記憶體，最多約一小時需重新連接。關閉網頁後板子可在授權仍有效且持續供電、連網時繼續；並非全天免登入。
- 最近一次成功連接的分頁日曆控制板子。活動名稱只在帶有相應暫時連線代碼的分頁顯示；其他分頁可見一般倒數狀態。
- 沒有聲音提醒、永久紀錄或多日曆合併。

## 程式架構

```text
Windows 瀏覽器：Google OAuth 登入、完整活動名稱、操作與畫面預覽
        │ USB localhost WebUI
        ▼
UNO Q Python ──HTTPS──> Google Calendar events.list
  │ calendar_api.py：唯讀同步、快取、行程正規化、專注建議
  │ agenda.py：選擇場景、暫停專注、英文關鍵字、跑馬燈點陣
  │ timer_core.py：專注／休息單調時鐘
  │ main.py：API、日曆優先權、背景同步、Bridge
  ▼
UNO Q MCU：接收四個 26-bit 整數組成的 104 像素畫面、顯示、失聯偵測
```

Google token 不寫磁碟、不回傳 API、不記錄主控台；Client ID 由使用者在網頁填入。瀏覽器 sessionStorage 只保存本機暫時連線代碼。不要拍攝開發者工具或將授權資訊寫進 repo。

## 五分鐘實機驗收

1. Google 主日曆建立「晚餐測試」，開始時間約現在 +2 分鐘，持續 2 分鐘，設為忙碌。
2. 新版 App 連接日曆後，把準備時間改為 1 分鐘並重新同步。
3. 不按開始專注：確認空閒 → READY → DINNER 跑馬燈與倒數 → 空閒。
4. 再建立一次活動，在空閒時啟動專注。確認準備時自動暫停，結束後仍保留剩餘時間，按繼續才恢復。
5. 更改活動結束時間並同步，確認倒數改變；取消活動後確認回到空閒。
6. 影片同時拍網頁與實體 UNO Q；不要只拍網頁模擬矩陣。

本機測試：`python -m unittest discover -s tests -v`。最新結果與尚未上板驗證項目見 VALIDATION.md。repo 可命名 `unoq-calendar-focus`。
